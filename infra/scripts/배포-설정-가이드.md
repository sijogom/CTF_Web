# CTF 플랫폼 배포 및 설정 가이드

## 스크립트 구분

| 스크립트 | 환경 | 용도 |
|---------|------|------|
| `infra/scripts/deploy.sh` | **Linux 서버** | 설치 + 실행 + 관리 (이 문서의 대상) |
| `infra/scripts/deploy-wsl.sh` | WSL2 | Windows WSL2 환경 배포 |
| `infra/scripts/server.sh` | WSL2 개발 | 개발 환경 전용 (Docker + 백엔드 + 프론트 개별 실행) |

**리눅스 서버에서는 `deploy.sh`만 사용합니다.** `server.sh`는 사용하지 않습니다.

---

## 1. 최초 설치

`CTF_Web/` 폴더를 리눅스 서버에 옮긴 후:

```bash
cd CTF_Web
# Windows에서 복사한 경우 deploy.sh 자체의 줄바꿈을 먼저 변환
sed -i 's/\r$//' infra/scripts/deploy.sh
bash infra/scripts/deploy.sh install
```

> **참고**: `deploy.sh install`이 실행되면 나머지 `.sh` 파일의 CRLF도 자동 변환됩니다.

이 명령어 하나로 **설치부터 서버 실행까지 전부 처리**됩니다:
1. Docker / Docker Compose 설치 (apt/dnf/yum 자동 감지)
2. 필수 패키지 설치 (openssl, curl, git)
3. 대화형 설정 (도메인, 관리자 계정, SMTP)
4. `.env` 파일 생성 (랜덤 비밀번호 자동 생성 + 검증)
5. JWT RS256 키 쌍 생성
6. 방화벽 설정 (ufw/iptables 자동 감지, 80/443/10000-60000 포트)
7. Docker 네트워크 생성
8. Docker 이미지 빌드
9. **서비스 시작**
10. 헬스체크 (5개 서비스 + HTTPS 검증)

설치 완료 후 바로 사이트에 접속할 수 있습니다.

---

## 2. 서비스 관리

설치 이후 서버를 관리할 때도 `deploy.sh`를 사용합니다:

```bash
# 시작 (서버 재부팅 후 등)
bash infra/scripts/deploy.sh start

# 중지
bash infra/scripts/deploy.sh stop

# 재시작
bash infra/scripts/deploy.sh restart

# 상태 확인 + 헬스체크
bash infra/scripts/deploy.sh status

# 코드 업데이트 후 재빌드 + 재시작
bash infra/scripts/deploy.sh update

# 로그 확인 (전체)
bash infra/scripts/deploy.sh logs

# 특정 서비스 로그 (예: 인증 서비스)
bash infra/scripts/deploy.sh logs ctf-auth

# 방화벽 규칙만 재설정
bash infra/scripts/deploy.sh firewall
```

## 3. 환경 설정 변경 (.env)

설치 후 도메인, 이메일, SMTP 등을 변경하려면 `infra/.env` 파일을 수정합니다:

```bash
nano infra/.env
```

**주요 설정 항목:**
| 변수 | 설명 | 예시 |
|------|------|------|
| `SITE_DOMAIN` | 사이트 도메인 | `ctf.university.ac.kr` |
| `SMTP_HOST` | SMTP 서버 | `smtp.gmail.com` |
| `SMTP_PORT` | SMTP 포트 | `587` |
| `SMTP_USER` | SMTP 사용자 | `admin@example.com` |
| `SMTP_PASSWORD` | SMTP 비밀번호 | (앱 비밀번호) |
| `SMTP_FROM` | 발신 주소 | `noreply@university.ac.kr` |
| `SMTP_TLS` | TLS 사용 여부 | `true` |

**관리자 계정 관련 (최초 설치 시만 적용):**
| 변수 | 설명 |
|------|------|
| `ADMIN_EMAIL` | 최초 관리자 이메일 |
| `ADMIN_USERNAME` | 최초 관리자 사용자명 |
| `ADMIN_PASSWORD` | 최초 관리자 비밀번호 |

> 관리자 계정은 최초 서비스 시작 시 한 번만 생성됩니다.
> 이후에는 `.env`를 바꿔도 반영되지 않으며, 웹 UI(설정 페이지)에서 변경해야 합니다.

`.env` 수정 후 반드시 재시작:
```bash
bash infra/scripts/deploy.sh restart
```

## 4. 설치 후 추가 설정

### 4-1. 도메인 DNS 설정
DNS 관리(가비아/Cloudflare 등)에서 A 레코드를 서버 IP로 설정:
```
A    @         <서버 IP>
A    www       <서버 IP>
```
HTTPS 인증서는 Caddy가 Let's Encrypt에서 자동 발급합니다.

### 4-2. SMTP 이메일 설정 (필수)

이메일 인증이 필수이므로 SMTP를 설정하지 않으면 회원가입 후 로그인이 불가합니다.

**방법 A: 설치 시 설정**
`deploy.sh install` 실행 중 SMTP 호스트를 입력하면 자동 설정됩니다.

초기 관리자 비밀번호는 화면에 출력하지 않으며, 설치 시 8자 이상을 직접 입력해야
합니다. 비밀번호를 비워 두면 설치가 중단됩니다.

**방법 B: .env 파일에서 설정**
`infra/.env`의 SMTP 항목을 수정한 후 `deploy.sh restart`

**방법 C: 관리자 페이지에서 설정**
1. 관리자 계정으로 로그인
2. 관리자 > 이메일 > SMTP 설정 탭
3. SMTP 정보 입력 후 저장
4. "테스트 메일 발송" 버튼으로 동작 확인

**Gmail SMTP:**
| 항목 | 값 |
|------|-----|
| SMTP 호스트 | `smtp.gmail.com` |
| 포트 | `587` |
| TLS | 사용 |
| 사용자 | Gmail 주소 |
| 비밀번호 | 앱 비밀번호 (Google 계정 > 보안 > 2단계 인증 > 앱 비밀번호) |

**Naver SMTP:**
| 항목 | 값 |
|------|-----|
| SMTP 호스트 | `smtp.naver.com` |
| 포트 | `587` |
| TLS | 사용 |
| 사용자 | 네이버 아이디 |
| 비밀번호 | 네이버 비밀번호 |

**SMTP 미설정 시 대안:**
관리자 페이지 > 유저 관리에서 미인증 사용자의 "수동 인증" 버튼으로 이메일 인증을 수동 완료할 수 있습니다.

### 4-3. 이메일 도메인 제한
현재 `@cju.ac.kr` 도메인만 회원가입이 가능합니다.
다른 도메인을 허용하려면 `services/auth/app/schemas/auth.py`의 `ALLOWED_EMAIL_DOMAINS`를 수정하세요:
```python
ALLOWED_EMAIL_DOMAINS = ["cju.ac.kr", "example.com"]
```

## 6. 문제 해결

### 서비스가 시작되지 않을 때
```bash
bash infra/scripts/deploy.sh logs ctf-auth
```

### 포트 충돌
```bash
ss -tlnp | grep -E '80|443|5432|6379'
```

### SSL 인증서 문제
Caddy가 Let's Encrypt 인증서를 자동 발급합니다. 실패 시:
- DNS A 레코드가 서버 IP를 가리키는지 확인
- 80/443 포트가 방화벽에서 열려있는지 확인
- `bash infra/scripts/deploy.sh logs ctf-caddy`로 에러 확인

### .env 검증 실패
`deploy.sh`는 시작 시 `.env`의 기본값(CHANGE_ME 등)을 자동 검사합니다.
수동 수정: `nano infra/.env`
